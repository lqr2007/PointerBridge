# PointerBridge

PointerBridge 用于将一台 Windows 设备上的触控笔输入，通过局域网映射到另一台 Windows 设备，让带笔屏幕成为目标电脑的远程笔输入设备。

项目使用 C#、WPF 和 .NET 8，包含两个独立程序：

| 程序 | 运行设备 | 作用 |
| --- | --- | --- |
| `PointerBridge_Client`（发送端） | 带触控笔的 Windows 设备 | 采集笔坐标、压感和按钮状态，通过 UDP 发送 |
| `PointerBridge_Server`（接收端） | 需要使用笔输入的 Windows 电脑 | 接收数据，通过 Windows 合成触控笔接口向桌面注入笔输入 |

数据流：触控笔 → Client 采集区域 → 局域网 UDP → Server → 目标电脑上的绘图应用。

## 功能

- 传输笔尖位置、悬停、落笔和抬笔状态。
- 支持压感、笔侧键和笔尾橡皮；实际效果取决于笔硬件、驱动及目标应用。
- 全屏采集，提供 `16:9`、`16:10`、`4:3` 三种目标屏幕宽高比。白色区域参与坐标映射，黑边不参与绘制。
- 按物理像素处理屏幕位置，并声明每显示器 DPI 感知，适配 Windows 显示缩放。
- 普通移动数据最高约 120 Hz，关键状态变化优先发送，静止时约每 250 ms 发送一次完整状态心跳。
- 接收端约 1 秒未收到有效更新时自动释放触控笔，避免断网后持续按下。
- 两端均提供调试窗口；发送端会记住上次成功初始化 UDP 目标时使用的 IP 地址。

## 环境要求

- 两台设备均运行 Windows，接收端至少需要 **Windows 10 1809（Build 17763）**，同时应满足所用 .NET 8 版本的操作系统支持要求。
- 发送端需要能够被 Windows/WPF 识别的触控笔设备。普通鼠标和手指触摸不会被当作笔输入发送。
- 接收端需要交互式桌面，目标应用需支持 Windows 笔输入 / Windows Ink。
- 两台设备处于同一可信局域网，允许发送端访问接收端的 UDP 监听端口，默认是 **38899**。
- 从源码构建需要 [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)。也可使用支持 .NET 8 的 Visual Studio 2022，并安装“.NET 桌面开发”工作负载。
- 运行依赖框架的发布版本需要 **.NET 8 Desktop Runtime（桌面运行时）**；自包含发布不需要额外安装运行时。

## 快速开始

### 1. 构建与启动

在 Windows 上进入仓库根目录，执行：

```powershell
dotnet build .\PointerBridge.sln -c Release
```

在接收端电脑启动 Server：

```powershell
dotnet run --project .\PointerBridge_Server\PointerBridge_Server.csproj -c Release
```

在带笔设备上启动 Client：

```powershell
dotnet run --project .\PointerBridge_Client\PointerBridge_Client.csproj -c Release
```

使用 Visual Studio 时，打开 `PointerBridge.sln`，分别将对应项目设为启动项目，在各自设备上运行。

### 2. 配置接收端

1. 在接收端运行 `ipconfig`，找到当前局域网网卡的 IP 地址，例如 `192.168.1.100`。
2. 打开 Server，设置“监听端口”（默认 `38899`），点击“开始监听”。
3. 如 Windows 防火墙提示网络访问权限，请允许可信专用网络上的访问。手动配置时，放行对应 UDP 入站端口，并尽量将来源限制为发送端 IP。
4. 在接收端主屏幕上打开绘图应用和空白画布，如应用提供输入接口选项，选择 Windows Ink。

### 3. 配置发送端

1. 将 Client 主窗口移到用于触控笔采集的屏幕上，采集窗口会覆盖该屏幕。
2. 选择与接收端主屏幕一致的“目标屏幕宽高比”，减少坐标映射变形。
3. 在“目标设备地址/端口”中填入接收端 IP 和监听端口，例如 `192.168.1.100` 和 `38899`。
4. 点击“启动连接”，在出现的白色区域内使用触控笔。
5. 在接收端确认悬停、轻重笔画、侧键和橡皮是否符合预期。

目标地址支持 IPv4 或 IPv6 字面地址，不支持直接填写主机名，也不能填写 `0.0.0.0` 或 `::`。端口范围为 `1～65535`，两端须保持一致。

> “启动连接”只设置 UDP 发送目标，没有握手过程，不代表接收端已在线。请通过接收端调试窗口和实际笔输入确认数据是否到达。

### 4. 退出采集与停止接收

在发送端**持续按住笔侧键**，先悬停至少 **1 秒**，再落笔并保持接触至少 **1 秒**，即可关闭全屏采集窗口。手势在黑边区域也有效；中途松开侧键、离开感应范围或在接触阶段抬笔，需要重新完成手势。

如果硬件未提供侧键状态，可使用键盘 `Alt+F4` 关闭当前采集窗口。

接收端点击“结束监听”会释放笔输入并销毁合成设备。关闭调试窗口不会停止采集、发送或注入。

## 调试与常见问题

两端点击菜单“调试”可查看笔状态。活动笔状态约每秒显示一次，日志频率不代表实际传输或注入频率。`X/Y` 和压感显示为 `0～1`，侧键“未知”表示驱动未提供可识别的按钮状态。

| 现象 | 排查方法 |
| --- | --- |
| 点击启动连接后，接收端仍在等待数据 | 检查 Server 是否已开始监听、目标 IP 和两端端口是否正确、防火墙是否放行 UDP；检查 Wi-Fi 是否开启访客隔离或客户端隔离 |
| Server 提示无法监听端口 | 检查端口是否被其他程序占用，或换一个端口并同步修改 Client |
| Client 显示未检测到触控笔 | 确认使用的是触控笔，驱动正常，并在白色区域内悬停或落笔；鼠标、手指不会触发笔采集 |
| 接收端有数据，但绘图应用无响应 | 确认应用位于主屏幕并支持 Windows Ink；检查是否使用了仅支持 WinTab 的模式，或目标窗口是否以更高权限运行 |
| 坐标或笔画比例不正确 | 将 Client 宽高比设为接收端主屏幕比例；当前接收端始终映射整个主屏幕，包含任务栏区域 |
| 侧键、压感或橡皮不起作用 | 先查看两端调试状态，再检查硬件、驱动和绘图应用支持情况；侧键的具体操作由目标应用决定 |
| 网络断开后仍短暂保持落笔 | 接收端在约 1 秒无有效更新后释放笔状态，后台每 100 ms 检查一次；也可点击“结束监听”立即停止 |
| 重启后只有 IP 被恢复 | 当前只保存上次成功初始化 UDP 目标时的 IP，端口和宽高比不会保存 |

发送端配置文件位于：

```text
%LOCALAPPDATA%\PointerBridge\Client\settings.json
```

## 发布程序

以下示例生成 Windows x64 自包含版本，便于分别复制到两台设备。请根据目标设备架构选择运行时标识，例如 ARM64 设备使用 `win-arm64`。

```powershell
dotnet publish .\PointerBridge_Client\PointerBridge_Client.csproj -c Release -r win-x64 --self-contained true -o .\publish\Client
dotnet publish .\PointerBridge_Server\PointerBridge_Server.csproj -c Release -r win-x64 --self-contained true -o .\publish\Server
```

将对应输出目录完整复制到目标设备，运行其中的 `PointerBridge_Client.exe` 或 `PointerBridge_Server.exe`。若使用 `--self-contained false`，目标设备需安装匹配架构的 .NET 8 Desktop Runtime。

## 当前限制与网络安全

- 当前接收端仅映射到**主屏幕**，没有目标显示器或应用内画布区域选择功能。发送端显示采集区域，不回传接收端画面。
- 接收端使用 Windows 合成触控笔接口，无需安装虚拟 HID 驱动；它不提供 WinTab 接口。高权限窗口、安全桌面及依赖特定硬件的应用可能不接受注入，程序不会自动提权。
- 当前协议不传输倾斜角、旋转或多笔输入。笔压和按钮的可用性受硬件与应用支持情况影响。
- UDP 不保证送达或顺序。程序会过滤旧包、重复包并处理超时，但丢包仍可能遗漏短暂的按下/松开状态；它不是无损笔迹记录工具。
- **数据包未加密，也未进行身份认证。** 开始监听后，符合接收规则的网络数据包可以控制桌面笔输入。仅在可信局域网内使用，限制防火墙来源，不要将监听端口映射或暴露到公网。
- 接收端同一时间维护一个活动来源，约 1 秒超时后才允许其他来源接管；该机制不构成身份认证。
